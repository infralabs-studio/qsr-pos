# QSR POS (MVP)

A local-first, offline-capable Quick Service Restaurant (QSR) Point of Sale MVP tailored for the Kenyan market, built with Django, PostgreSQL, and React (Vite).

## Architecture

- **Deployment:** Single-terminal deployment, designed for cloud synchronization.
- **Primary keys:** UUIDs on all business tables so records created offline can sync without ID collisions.
- **Reliability:** Transactional Outbox pattern for background work, and a PostgreSQL trigger that makes the audit log append-only.
- **Kenya-specific workflows:** M-PESA payments (Daraja STK push, plus a manual till-entry fallback for when the internet is down). eTIMS integration is planned; the approach is still an open decision.

## Prerequisites

- Docker and Docker Compose v2
- `curl` (used by the setup script's health check)
- Python 3.12 (optional, only for a host virtualenv / IDE tooling)
- Git Bash or WSL (recommended on Windows)

## Quick Start

```bash
# Clone the repository
git clone https://github.com/infralabs-studio/qsr-pos.git
cd qsr-pos

# Make the setup script executable (Linux/macOS/Git Bash)
chmod +x scripts/setup.sh

# Bootstrap everything
# Add --local to also create backend/.venv with dev dependencies for IDE linting
./scripts/setup.sh
```

The setup script will:

1. Copy `.env.example` to `.env` and generate secrets for `DJANGO_SECRET_KEY` and `POSTGRES_PASSWORD`.
2. Build and start the PostgreSQL and backend containers.
3. Apply database migrations (the backend container runs `migrate` on start).
4. Wait for the API health check to pass.

When it finishes:

| What | URL |
| --- | --- |
| API health check | http://localhost:8000/healthz/ |
| Django admin | http://localhost:8000/admin/ |
| PostgreSQL | `127.0.0.1:5432` (host access only) |

## Environment Variables

All variables live in `.env` (git-ignored). Only `.env.example` is committed, and it contains no real secrets.

| Variable | Description | Default in `.env.example` |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | Django secret key. Generated by `setup.sh`. | `change-me` |
| `DJANGO_DEBUG` | Enable Django debug mode. Use `False` outside local development. | `True` |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated allowed hosts. | `localhost,127.0.0.1` |
| `CORS_ALLOWED_ORIGINS` | Comma-separated frontend origins (Vite dev server). | `http://localhost:5173` |
| `POSTGRES_DB` | Database name. | `qsr_pos` |
| `POSTGRES_USER` | Database user. | `qsr` |
| `POSTGRES_PASSWORD` | Database password. Generated by `setup.sh`. | `change-me` |
| `POSTGRES_HOST` | `localhost` when running Django on your machine. Docker Compose overrides this to `db` inside the container. | `localhost` |
| `POSTGRES_PORT` | Host port for PostgreSQL. | `5432` |
| `MPESA_ENV` | `sandbox` or `production`. | `sandbox` |
| `MPESA_CONSUMER_KEY` / `MPESA_CONSUMER_SECRET` | Daraja credentials. Never commit these. | _(blank)_ |
| `MPESA_SHORTCODE` / `MPESA_PASSKEY` / `MPESA_CALLBACK_URL` | Daraja STK push configuration. | _(blank)_ |
| `POS_PRICES_TAX_INCLUSIVE` | `True` if menu prices already include VAT, `False` if tax is added on top. | `True` |
| `CLOUD_SYNC_URL` | Cloud ingest endpoint the Outbox drains to. Blank disables sync. | _(blank)_ |
| `CLOUD_API_KEY` | Shared secret for the cloud ingest endpoint. | `change-me` |
| `CLOUD_MOCK_ENABLED` | Enables the mock receiver. Set only on the mock cloud service. | `False` |
| `OUTBOX_BATCH_SIZE` / `OUTBOX_POLL_SECONDS` / `OUTBOX_LEASE_SECONDS` | Drain batch size, poll interval, and the lease before a dead worker's rows are reclaimed. | `50` / `5` / `60` |
| `OUTBOX_BACKOFF_BASE_SECONDS` / `OUTBOX_BACKOFF_CAP_SECONDS` | Retry backoff while the cloud is unreachable. | `2` / `60` |
| `RECONCILIATION_WINDOW_MINUTES` / `RECONCILIATION_GRACE_HOURS` | Time window for near matches, and hours before an unmatched manual payment goes to manager review. | `30` / `24` |
| `MPESA_RECORDS_URL` | Where reconciliation looks up M-PESA transactions. Blank disables it. | _(blank)_ |
| `RECONCILE_POLL_SECONDS` | Seconds between reconciliation passes. | `30` |

## Useful Commands

Create a superuser (admin access):

```bash
docker compose exec backend python manage.py createsuperuser
```

Run the backend test suite:

```bash
docker compose exec backend python manage.py test
```

Run formatting, linting, and type checks (the same checks CI runs):

```bash
docker compose exec backend sh -c "black --check . && flake8 && mypy ."
```

Check that no model changes are missing a migration:

```bash
docker compose exec backend python manage.py makemigrations --check --dry-run
```

View backend logs:

```bash
docker compose logs -f backend
```

Stop containers (keeps the database):

```bash
docker compose down
```

Stop containers and wipe the database volume:

```bash
docker compose down -v
```

## Continuous Integration

Every pull request runs `.github/workflows/ci.yml`:

1. `black --check` (formatting)
2. `flake8` (linting)
3. `mypy` (type checking)
4. `makemigrations --check` (migrations are committed and up to date)
5. `manage.py test` (against a PostgreSQL service container)

## Troubleshooting

- **Port 5432 already in use:** set a different `POSTGRES_PORT` in `.env`, then re-run `./scripts/setup.sh`.
- **API never becomes healthy:** check `docker compose logs backend`.
- **Secrets look wrong or you want a fresh start:** delete `.env`, run `docker compose down -v`, then re-run `./scripts/setup.sh`.
- **Never commit `.env`.** Verify with `git ls-files | grep -E '(^|/)\.env$'`, which should print nothing.
